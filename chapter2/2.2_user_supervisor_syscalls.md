# 2.2 用户模式、监管者模式与系统调用 (User mode, supervisor mode, and system calls)

强隔离要求在应用程序和操作系统之间存在一道严格的边界（hard boundary）。绝不应允许应用程序扰乱操作系统或其他程序的运行，即使该应用程序存在 Bug 或是被恶意编写的。为了实现强隔离，操作系统必须做出周全的安排，确保应用程序不能修改（甚至不能读取）操作系统的数据结构和指令，并且应用程序绝对不能访问其他进程的内存。

CPU 为强隔离提供了硬件层面的支持。例如，RISC-V 架构拥有三种限制代码行为的特权级别（privilege levels）：机器模式（machine mode）、监管者模式（supervisor mode）和用户模式（user mode）。在机器模式下执行的指令拥有完全特权；CPU 启动时默认处于机器模式。机器模式主要用于在计算机引导（boot）期间进行初始设置。xv6 仅在机器模式下作短暂执行，随后便会切换到监管者模式。

在监管者模式下，CPU 被允许执行特权指令（privileged instructions）：例如，启用和禁用中断、读写保存着页表地址的寄存器等。如果处于用户模式的应用程序试图执行一条特权指令，CPU 将不会执行该指令，而是会“陷入（trap）”到监管者模式下的一段特定代码中，该代码随后可以终止这个违规的应用程序。第 1 章中的图 1.1 说明了这种组织架构。应用程序只能执行用户模式指令（例如，执行数字加法等），这被称为运行在用户空间（user space）；而运行在监管者模式下的软件不仅能执行普通指令，还能执行特权指令，这被称为运行在内核空间（kernel space）。运行在内核空间（或监管者模式下）的软件就被称为内核（kernel）。

应用程序通过诸如 `read` 这样的系统调用与内核进行交互。绝不允许应用程序直接调用内核函数或访问内核的内存。RISC-V 提供了 `ecall` 指令来实现系统调用；该指令会将 CPU 从用户模式切换到监管者模式，并跳转到一个由内核指定的入口点（entry point）。一旦 CPU 切换到了监管者模式，内核就可以对系统调用的参数进行校验（例如，检查传递给系统调用的地址是否真的属于该应用程序的内存范围），决定是否允许该应用程序执行其所请求的操作（例如，检查该应用程序是否有权限写入指定的文件），然后选择拒绝或执行该操作。由内核来全权掌控过渡到监管者模式的入口点是至关重要的；如果允许应用程序来决定内核入口点，那么恶意程序就可以钻空子，比如选择在绕过参数校验的地方直接进入内核。
