# 2.6 代码剖析：启动 xv6、首个进程与系统调用 (Code: starting xv6, the first process and system call)

为了让 xv6 更加具体，我们将概述内核是如何启动并运行第一个进程的。后续章节将更详细地描述本概述中出现的各项机制。请仔细阅读 `kernel/entry.S`、`kernel/start.c`、`kernel/main.c` 和 `user/init.c`。

当 RISC-V 计算机上电时，它会初始化自身，并运行存储在只读存储器（ROM）中的引导加载程序（boot loader）。引导加载程序会将 xv6 内核复制到物理地址 `0x80000000` 处的内存中。它之所以将内核放置在 `0x80000000` 而不是 `0x0`，是因为 `0x0` 到 `0x80000000` 的地址范围已被 I/O 设备所占用。

随后，引导加载程序跳转到 xv6 的起始点 `_entry` (1006)。RISC-V 在启动时是禁用分页硬件（paging hardware）的：此时虚拟地址直接映射到物理地址。`_entry` 处的指令设置了一个栈（stack），以便 xv6 能够运行 C 代码。xv6 在文件 `start.c` (1060) 中为这个栈（名为 `stack0`）声明了空间。`_entry` 处的代码将地址 `stack0+4096`（即栈顶）加载到栈指针寄存器 `sp` 中，这是因为 RISC-V 上的栈是向下生长的。现在内核拥有了栈，`_entry` 便开始跳转执行 `start` (1064) 处的 C 代码。

`start` 函数执行了一些 CPU 仅允许在机器模式（machine mode）下进行的设置操作，其中最关键的一步是对时钟芯片进行编程以生成定时器中断（timer interrupts）。接着，`start` 使用 RISC-V 的 `mret` 指令切换到监管者模式（supervisor mode），并跳转到 `main` (1160)。`mret` 指令需要一些前置设置：`start` 将 `mstatus` 寄存器中的先前特权模式（previous privilege mode）设置为监管者模式，通过将 `main` 的地址写入 `mepc` 寄存器来设置目标跳转地址，通过向页表寄存器 `satp` 写入 `0` 来禁用监管者模式下的虚拟地址转换，并将所有的中断和异常委托（delegates）给监管者模式。

在 `main` (1160) 初始化了若干设备和子系统之后，它通过调用 `userinit` (2327) 创建了第一个进程。所有新创建的进程都会在内核的 `forkret` (2653) 处开始执行。作为第一个进程的特例，`forkret` 会调用 `kexec` 来加载用户程序 `/init`。

调用 `kexec` 后，`forkret` 在 `/init` 进程中返回用户空间。`init` (7764) 会在需要时创建一个新的控制台设备文件，然后将其作为文件描述符 0、1 和 2 打开。接着，它在控制台上启动一个 shell。

至此，系统已全面启动并运行（The system is up）。
