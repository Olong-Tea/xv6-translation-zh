# 2.5 进程概述 (Process overview)

在 xv6（以及其他 Unix 操作系统）中，隔离的基本单位是进程（process）。进程抽象防止了一个进程破坏或窥探另一个进程的内存、CPU、文件描述符等资源。它同时也防止了进程破坏内核本身，从而使得进程无法颠覆内核的隔离机制。内核必须小心翼翼地实现进程抽象，因为一个充满 Bug 或恶意的应用程序可能会欺骗内核或硬件去做一些坏事（例如，绕过隔离）。内核用来实现进程的机制包括：用户/监管者模式标志、地址空间，以及线程的时间片轮转（time-slicing）。

为了帮助强制实施隔离，进程抽象为程序提供了一种错觉（illusion）：让程序以为自己拥有一台专属的私有机器。进程为程序提供了一个看似私有的内存系统（即地址空间），其他进程无法对其进行读写。进程还为程序提供了一个看似专属的 CPU，用来执行该程序的指令。

xv6 使用由硬件实现的页表（page tables）来为每个进程提供独立的地址空间。RISC-V 的页表将虚拟地址（virtual address，即 RISC-V 指令所操作的地址）转换（或“映射”）为物理地址（physical address，即 CPU 发送到主存的地址）。

xv6 为每个进程维护一个独立的页表，该页表定义了该进程的地址空间。正如之前图 2.3 所示，一个地址空间包含了从虚拟地址零开始的进程用户内存。首先是指令（代码段），接着是全局变量（数据段），然后是栈（stack），最后是一个进程可以根据需要进行扩展的“堆（heap）”区（用于 `malloc` 分配）。有几个因素限制了进程地址空间的最大尺寸：RISC-V 上的指针是 64 位宽的；硬件在页表中查找虚拟地址时只使用低 39 位；而 xv6 只使用了这 39 位中的 38 位。因此，最大地址为 2^38 - 1 = 0x3fffffffff，这也就是 `MAXVA` (0899)。

在地址空间的顶部，xv6 放置了一个跳板页（trampoline page，4096 字节）和一个陷入帧页（trapframe page）。xv6 使用这两个页来完成进出内核的转换；跳板页包含了进出内核的转换代码，而陷入帧则是内核用来保存进程的用户态寄存器的地方，这将在第 4 章中详细解释。

xv6 内核为每个进程维护着许多状态信息，它将这些信息统一收集在一个 `struct proc` 结构体 (2034) 中（译者注：即操作系统理论中的 PCB，进程控制块）。一个进程最重要的几项内核状态包括：它的页表、它的内核栈（kernel stack）以及它的运行状态（run state）。我们将使用 `p->xxx` 这种符号来指代 `proc` 结构体中的元素；例如，`p->pagetable` 就是一个指向该进程页表的指针。

**读到这里，请务必去阅读 `kernel/proc.h` 文件，它定义了 `struct proc`。** 理解 xv6 的源代码比阅读本书更重要；你应该将阅读源码放在首位，并在需要澄清代码逻辑时再来查阅本书。有些代码的意图一开始可能并不明显，但进一步的阅读和在源码中搜索会大有裨益。请随意探索甚至修改这些代码。

每个进程都有一个控制线程（thread of control，或简称线程），它保存着执行该进程所需的状态。在任何给定时刻，一个线程可能正在某个 CPU 上执行，也可能处于挂起状态（suspended，即当前未执行，但在未来可以恢复执行）。为了在不同的进程之间切换 CPU，内核会挂起当前在该 CPU 上运行的线程，保存它的状态，然后恢复另一个进程之前被挂起线程的状态。线程的许多状态（如局部变量、函数调用的返回地址）都存储在线程的栈中。每个进程拥有两个栈：一个用户栈（user stack）和一个内核栈（`p->kstack`）。当进程执行用户指令时，只有它的用户栈在使用中，其内核栈是空的。当进程进入内核时（由于系统调用或中断），内核代码会在该进程的内核栈上执行；当进程在内核中时，其用户栈仍然包含着保存的数据，但并不处于活跃使用状态。一个进程的线程在其用户栈和内核栈的活跃使用之间交替切换。内核栈是独立存在的（并且受到保护，不受用户代码的干扰），因此即使进程破坏了自己的用户栈，内核依然能够安全地执行。

进程的用户代码可以通过执行 RISC-V 的 `ecall` 指令发起系统调用。该指令会切换到监管者模式，并将程序计数器（PC）更改为内核定义的入口点。入口点处的代码会切换到该进程的内核栈，并执行实现该系统调用的内核指令。当系统调用完成时，内核通过执行 `sret` 指令返回用户空间，该指令会切换回用户模式，并在紧接着系统调用指令之后恢复执行用户指令。进程的线程可以在内核中“阻塞（block）”以等待 I/O，并在 I/O 完成后从它离开的地方恢复执行。

`p->state` 指示了该进程的状态：是已分配、就绪准备运行、当前正在 CPU 上运行、正在等待 I/O，还是正在退出。

`p->pagetable` 保存了该进程的页表，其格式严格遵循 RISC-V 硬件的期望。当在用户空间执行某个进程时，xv6 会指示分页硬件使用该进程的 `p->pagetable`。进程的页表同时也是一份记录，记录了分配用于存储该进程内存的物理页地址。

总结来说，进程捆绑了两个核心设计理念：一个**地址空间**（赋予进程拥有专属内存的错觉），以及一个**线程**（赋予进程拥有专属 CPU 的错觉）。在 xv6 中，一个进程由一个地址空间和一个线程组成。在现实世界更复杂的操作系统中，一个进程可能会拥有多个线程，以充分利用多核 CPU 的性能。
