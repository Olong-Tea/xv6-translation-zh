# 第二章：操作系统组织架构 (Operating system organization)

操作系统的一个关键需求是同时支持多项活动。例如，我们可能会使用第 1 章中的 `fork` 和 `exec` 系统调用来同时启动一个编译器和一个文本编辑器作为独立的进程。操作系统必须在这些进程之间分时共享（time-share）CPU 和内存等资源。操作系统还必须在进程之间建立隔离（isolation）。如果一个进程出现 Bug 并发生故障，它绝对不应该影响到其他无关的进程。然而，完全彻底的隔离又过于严苛了，因为进程之间也应该能够进行有意的交互（interact）；管道（pipelines）就是一个很好的例子。因此，操作系统必须满足三个核心需求：**多路复用（multiplexing）**、**隔离（isolation）**和**交互（interaction）**。

本章将概述操作系统是如何组织架构以实现这三个需求的。事实证明，实现的方法有很多，但本文将重点探讨围绕**宏内核（monolithic kernel）**展开的主流设计，这也是许多 Unix 操作系统所采用的架构。本章还将概述 xv6 进程（process）——它是 xv6 中实现隔离的基本单位。

xv6 运行在多核（multi-core）[^1] RISC-V 微处理器上，其大部分底层功能（例如它的进程实现）都是专门针对 RISC-V 架构的。RISC-V 是一种 64 位 CPU，而 xv6 是用 “LP64” C 语言编写的，这意味着在 C 语言中，长整型（long, L）和指针（pointers, P）是 64 位的，但整型（int）是 32 位的。本书假定读者曾在某种架构上进行过少量的机器级（汇编）编程，并会在遇到 RISC-V 特有的概念时随时进行介绍。官方的用户级指令集架构 (ISA) 文档 [^2] 和特权架构文档 [^3] 提供了完整的规范。你也可以参考《RISC-V 手册：一本开源指令集的指南》（*The RISC-V Reader: An Open Architecture Atlas*）[^15]。

在一台完整的计算机中，CPU 周围环绕着各种支持硬件，其中大部分以 I/O 接口的形式存在。xv6 是针对 QEMU 模拟器中 `-machine virt` 选项所模拟的支持硬件而编写的。这些硬件包括随机存取存储器（RAM）、包含引导代码的只读存储器（ROM）、连接用户键盘和屏幕的串行接口（serial connection），以及用于存储的磁盘。

---
[^1]: 在本文中，“多核（multi-core）”指的是共享内存但并行执行的多个 CPU，每个 CPU 都拥有自己独立的一套寄存器。本文有时会将“多处理器（multiprocessor）”作为多核的同义词使用，尽管“多处理器”也可以更具体地指代包含多个独立处理器芯片的计算机。
[^2]: 留白：RISC-V 用户级 ISA 文档。
[^3]: 留白：RISC-V 特权架构文档。
[^15]: 留白：The RISC-V Reader: An Open Architecture Atlas.
