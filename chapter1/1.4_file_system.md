# 1.4 文件系统 (File system)

xv6 文件系统提供了数据文件（包含未解释的字节数组）和目录（包含对数据文件和其他目录的命名引用）。这些目录形成了一棵树，起始于一个特殊的目录，称为根目录（root）。像 `/a/b/c` 这样的路径，指的是根目录 `/` 下的目录 `a` 中的目录 `b` 里的文件或目录 `c`。不以 `/` 开头的路径是相对于调用进程的当前目录（current directory）进行解析的，当前目录可以通过 `chdir` 系统调用进行更改。以下两个代码片段打开的是同一个文件（假设所有涉及的目录都存在）：

```c
chdir("/a");
chdir("b");
open("c", O_RDONLY);
```

```c
open("/a/b/c", O_RDONLY);
```

第一个代码片段将进程的当前目录更改为了 `/a/b`；第二个片段则既没有引用也没有更改进程的当前目录。

系统提供了一些用于创建新文件和目录的系统调用：`mkdir` 创建一个新目录，带有 `O_CREATE` 标志的 `open` 创建一个新的数据文件，而 `mknod` 创建一个新的设备文件。以下示例演示了这三种调用：

```c
mkdir("/dir");
fd = open("/dir/file", O_CREATE|O_WRONLY);
close(fd);
mknod("/console", 1, 1);
```

`mknod` 创建一个指向设备的特殊文件。与设备文件关联的是主设备号和次设备号（major and minor device numbers，即传给 `mknod` 的两个参数），它们唯一地标识了一个内核设备。当进程随后打开一个设备文件时，内核会将 `read` 和 `write` 系统调用转移到内核设备的实现上，而不是将它们传递给文件系统。

文件名（name）与文件本身是截然不同的概念；同一个底层的文件（被称为 inode 或索引节点）可以有多个名称，这些名称被称为链接（links）。每个链接由目录中的一个条目组成；该条目包含一个文件名和一个指向 inode 的引用。inode 保存了关于文件的元数据（metadata），包括其类型（文件、目录或设备）、长度、文件内容在磁盘上的位置，以及指向该文件的链接数量。

`fstat` 系统调用从文件描述符所引用的 inode 中检索信息。它会填充一个 `struct stat` 结构体，该结构体在 `stat.h` (4050) 中定义如下：

```c
#define T_DIR     1   // Directory (目录)
#define T_FILE    2   // File (文件)
#define T_DEVICE  3   // Device (设备)

struct stat {
  int dev;     // File system's disk device (文件系统所在的磁盘设备)
  uint ino;    // Inode number (Inode 编号)
  short type;  // Type of file (文件类型)
  short nlink; // Number of links to file (指向该文件的链接数)
  uint64 size; // Size of file in bytes (文件大小，以字节为单位)
};
```

`link` 系统调用会创建一个新的文件系统名称，该名称指向与现有文件相同的 inode。以下代码片段创建了一个同时被命名为 `a` 和 `b` 的新文件：

```c
open("a", O_CREATE|O_WRONLY);
link("a", "b");
```

对 `a` 进行读取或写入，与对 `b` 进行读取或写入是完全一样的。每个 inode 都由一个唯一的 inode 编号标识。在上述代码执行完毕后，我们可以通过检查 `fstat` 的结果来判断 `a` 和 `b` 指向的是否是相同的底层内容：对它们调用 `fstat` 都会返回相同的 inode 编号（`ino`），并且链接数（`nlink`）会被设置为 2。

`unlink` 系统调用会从文件系统中移除一个名称。只有当文件的链接数为零，并且没有任何文件描述符引用它时，该文件的 inode 以及存放其内容的磁盘空间才会被释放。因此，如果在最后一段代码的末尾加上：

```c
unlink("a");
```

那么该 inode 和文件内容仍然可以通过 `b` 访问。此外，

```c
fd = open("/tmp/xyz", O_CREATE|O_RDWR);
unlink("/tmp/xyz");
```

这是一种创建无名临时 inode 的惯用手法，当进程关闭 `fd` 或退出时，这个 inode 就会被自动清理掉。

Unix 提供了一些可以从 shell 中调用的文件实用工具，作为用户级程序运行，例如 `mkdir`、`ln` 和 `rm`。这种设计允许任何人通过添加新的用户级程序来扩展命令行接口。事后看来，这个方案似乎是理所当然的，但在 Unix 诞生的那个时代，其他系统通常会将此类命令内置到 shell 中（甚至将 shell 内置到内核中）。

一个例外是 `cd`，它是内置在 shell 中的 (8021)。`cd` 必须改变 shell 本身的当前工作目录。如果将 `cd` 作为一个常规命令来运行，那么 shell 会 `fork` 出一个子进程，由子进程来运行 `cd`，这样 `cd` 改变的就只会是那个子进程的工作目录。而父进程（即 shell 自身）的工作目录将不会发生任何改变。
