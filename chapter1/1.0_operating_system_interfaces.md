# 第一章：操作系统接口 (Operating system interfaces)

  操作系统的职责是在多个程序之间共享计算机资源，并提供比底层硬件自身支持更丰富的服务集合。操作系统对底层硬件进行管理和抽象，使得例如文字处理软件之类的程序无需关心当前使用的是哪种类型的磁盘硬件。操作系统在多个程序间共享硬件，使它们能够（或看起来能够）同时运行。最后，操作系统提供了受控的程序交互方式，使程序之间能够共享数据或协同工作。

  操作系统通过接口（interface）向用户程序提供服务。事实证明，设计一个优秀的接口是一件难事。一方面，我们希望接口简单且精简（narrow），因为这更容易确保底层实现的正确性。另一方面，我们又常常忍不住想要向应用程序提供许多复杂高级的功能。解决这种张力的诀窍在于：设计的接口应当只依赖少数几个基本机制，但这些机制可以通过组合提供极大的通用性（generality）。

  本书使用一个单一的操作系统作为具体示例，来阐释操作系统的核心概念。这个名为 xv6 的操作系统，提供了由 Ken Thompson 和 Dennis Ritchie 所设计的 Unix 操作系统 [^17] 引入的基础接口，并模仿了 Unix 的内部设计。

  Unix 提供了一个精简的接口，其内部机制能很好地组合，从而提供了令人惊叹的通用性。这个接口取得了巨大的成功，以至于现代操作系统——BSD、Linux、macOS、Solaris，甚至在某种程度上的 Microsoft Windows——都采用了类 Unix（Unix-like）的接口。理解 xv6 是理解上述任何系统以及许多其他系统的良好开端。

  ![图 1.1：内核与两个用户进程]

  正如 图 1.1 所示，xv6 采用了传统的内核（kernel）形式。内核是一个特殊的程序，负责为正在运行的程序提供服务。每一个正在运行的程序被称为一个进程（process），它拥有包含指令、数据和栈（stack）的内存。指令实现了程序的计算逻辑，数据是计算逻辑作用的变量，而栈则用于组织程序的函数调用。一台计算机通常有多个进程，但只有一个内核。

  当进程需要调用内核服务时，它会发起一个系统调用（system call），这是操作系统接口中的一种调用。系统调用会进入内核；内核执行相应的服务后返回。因此，进程总是在用户空间（user space）和内核空间（kernel space）的执行之间交替进行。

  就像后续章节将详细描述的那样，内核利用 CPU 提供的硬件保护机制 [^1] 来确保在用户空间执行的每个进程只能访问自己的内存。内核在执行时拥有实现这些保护所需的硬件特权（hardware privileges）；而用户程序执行时则没有这些特权。当用户程序发起系统调用时，硬件会提升特权级别（privilege level），并开始执行内核中预先安排好的函数。

  内核提供的系统调用集合构成了用户程序所能看到的接口。xv6 内核提供了传统 Unix 内核所提供的服务和系统调用的一个子集。图 1.2 列出了 xv6 的所有系统调用。

  本章的其余部分将概述 xv6 的服务——包括进程、内存、文件描述符、管道和文件系统——并通过代码片段，以及探讨 shell（Unix 的命令行用户接口）如何使用这些服务，来对它们进行说明。shell 对系统调用的使用方式，生动地展示了这些调用在设计上是多么地精妙。

  shell 本身只是一个普通的程序，负责从用户那里读取命令并执行。shell 作为用户程序而不是内核的一部分，恰恰证明了系统调用接口的强大之处：shell 并没有任何特殊特权。这也意味着 shell 很容易被替换；正因如此，现代 Unix 系统有多种 shell 可供选择，每种都有自己的用户界面和脚本特性。xv6 的 shell 则是对 Unix Bourne shell 核心精髓的一种简单实现。

  xv6 shell 的实现可以在源码的 (7850) 处找到。（该链接是一个超链接，指向 `https://github.com/mit-pdos/xv6-riscv/` 中相关的 xv6 源代码，具体的数字对应的是 `xv6-src-booklet.pdf` 中的页数和行号，这种标注方式借鉴了《UNIX 6th Edition 源码剖析》[^11]）。一个良好的学习习惯是：先尝试自己独立阅读源代码（在你最喜欢的开发环境中、在 GitHub 上，或者使用 PDF 阅读器），然后再回到本书。当你读完本书时，你应该能够在不需要查阅本书的情况下理解 xv6 源代码的每一行。

[^1]: 本文通常使用 CPU（Central Processing Unit 的缩写）这个术语来指代执行计算的硬件单元。
