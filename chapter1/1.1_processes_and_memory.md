# 1.1 进程与内存 (Processes and memory)

xv6 的进程由用户空间内存（包含指令、数据和栈）以及内核私有的单进程状态组成。xv6 对进程进行分时复用（time-shares）：它在等待执行的进程集合中，透明地切换可用的 CPU 资源。当一个进程不在执行状态时，xv6 会保存该进程的 CPU 寄存器，并在下次运行该进程时恢复它们。内核会为每个进程关联一个进程标识符（PID）。

| 系统调用 (System call) | 描述 (Description) |
| :--- | :--- |
| `int fork()` | 创建一个进程，返回子进程的 PID。 |
| `int exit(int status)` | 终止当前进程；将状态（status）报告给 `wait()`。无返回值。 |
| `int wait(int *status)` | 等待子进程退出；将退出状态存入 `*status` 中；返回子进程的 PID。 |
| `int kill(int pid)` | 终止 PID 为指定值的进程。返回 0，出错则返回 -1。 |
| `int getpid()` | 返回当前进程的 PID。 |
| `int pause(int n)` | 暂停 `n` 个时钟节拍（clock ticks）。 |
| `int exec(char *file, char *argv[])` | 加载一个文件并带参数执行它；仅在出错时返回。 |
| `char *sbrk(int n)` | 将进程的内存增加 `n` 个字节（初始化为零）。返回新内存的起始地址。 |
| `int open(char *file, int flags)` | 打开一个文件；`flags` 指示读/写模式；返回一个文件描述符（fd）。|
| `int write(int fd, char *buf, int n)` | 将缓冲区 `buf` 中的 `n` 个字节写入文件描述符 `fd`；返回写入的字节数。 |

| `int mknod(char *file, int, int)` | 创建一个设备文件。 |
| `int fstat(int fd, struct stat *st)` | 将一个已打开文件的信息存入 `*st` 中。 |
| `int link(char *file1, char *file2)` | 为文件 `file1` 创建另一个名称（`file2`）。 |
| `int unlink(char *file)` | 删除一个文件。 |

进程可以使用 `fork` 系统调用创建一个新进程。`fork` 会为新进程提供一份与调用进程内存完全相同的拷贝：`fork` 将调用进程的指令、数据和栈复制到新进程的内存中。`fork` 会在原始进程和新进程中分别返回。在原始进程中，`fork` 返回新进程的 PID。在新进程中，`fork` 返回 0。原始进程和新进程通常被称为父进程（parent）和子进程（child）。

例如，考虑以下用 C 编程语言 [^7] 编写的代码片段：

```c
int pid = fork();
if(pid > 0){
    printf("parent: child=%d\n", pid);
    pid = wait((int *) 0);
    printf("child %d is done\n", pid);
} else if(pid == 0){
    printf("child: exiting\n");
    exit(0);
} else {
    printf("fork error\n");
}
```

exit 系统调用会导致调用进程停止执行，并释放诸如内存和已打开文件等资源。`exit` 接收一个整型的状态参数（`status`），按照惯例，`0` 表示成功，`1` 表示失败。`wait` 系统调用返回当前进程已退出（或被终止）的子进程的 `PID`，并将该子进程的退出状态复制到传递给 `wait` 的地址处；如果调用者的子进程都还没有退出，`wait` 会等待直到有一个子进程退出。如果调用者没有子进程，`wait` 立即返回 `-1`。如果父进程不关心子进程的退出状态，它可以向 `wait` 传递地址 `0`。

在上面的例子中，输出的这两行内容：
```
Plaintext
parent: child=1234
child: exiting
```

可能会以任意顺序出现（甚至交织在一起），这取决于父进程和子进程谁先执行到它的 `printf` 调用。子进程退出后，父进程的 `wait` 调用会返回，从而使父进程打印出：
```
Plaintext
parent: child 1234 is done
```
尽管子进程启动时拥有父进程内存的一份拷贝，但父子进程在各自独立的内存和寄存器中执行：改变其中一个进程的变量不会影响另一个。例如，当 `wait` 的返回值存储到父进程的 `pid` 变量中时，它不会改变子进程中的 `pid` 变量。子进程中 `pid` 的值仍将是 `0`。

`exec` 系统调用会从文件系统中存储的文件加载新的内存映像，以此替换调用进程的内存。该文件必须具有特定的格式，以指定文件中的哪部分是指令、哪部分是数据、从哪条指令开始执行等。xv6 使用 ELF 格式，第 3 章会对此进行更详细的讨论。通常，该文件是程序源代码编译后的产物。当 `exec` 执行成功时，它不会返回到调用程序；相反，从文件加载的指令会从 ELF 头部声明的入口点开始执行。`exec` 接收两个参数：包含可执行文件的文件名，以及一个字符串参数数组。例如：

```c
char *argv[3];
argv[0] = "echo";
argv[1] = "hello";
argv[2] = 0;
exec("/bin/echo", argv);
printf("exec error\n");
```
这段代码会将调用程序替换为正在运行的 `/bin/echo` 程序实例，并附带参数列表 `echo hello`。大多数程序会忽略参数数组的第一个元素，按照惯例，该元素通常是程序的名称。

xv6 的 shell 代表用户使用上述调用来运行程序。shell 的主体结构很简单；参见 main (8001)。主循环通过 `getcmd` 从用户那里读取一行输入。接着它调用 `fork`，创建一个 shell 进程的副本。父进程调用 `wait`，而子进程则运行该命令。例如，如果用户在 shell 中输入了 `“echo hello”`，那么 `runcmd` 将被调用，并以 `“echo hello” `作为参数。runcmd (7903) 负责运行实际的命令。对于 `“echo hello”`，它将调用 `exec (7927)`。如果 `exec` 执行成功，那么子进程将执行 `echo` 的指令，而不是 `runcmd` 的指令。在某个时刻，`echo` 会调用 `exit`，这将导致父进程从 `main (8001)` 的 `wait` 调用中返回。

你可能会想，为什么不把 `fork` 和 `exec` 合并成一个单一的调用；稍后我们将看到，shell 正是在其 I/O 重定向的实现中利用了这种分离设计。为了避免创建一个完全相同的进程然后又立刻（通过 `exec`）将其替换掉所造成的浪费，操作系统内核针对这种用例，利用写时复制（copy-on-write，参见第 5 章）等虚拟内存技术来优化 `fork` 的实现。

xv6 隐式地分配大部分用户空间内存：`fork` 分配子进程拷贝父进程内存所需的内存空间，而 `exec` 会分配足够的内存来容纳可执行文件。在运行时需要更多内存的进程（也许是为了执行 `malloc`）可以调用 `sbrk(n)`，将它的数据内存增加 `n` 个字节（初始化为零）；`sbrk` 返回新内存的起始位置。

[^7]: 留白：C programming language.
