# 1.5 现实世界 (Real world)

Unix 将“标准”文件描述符、管道以及用于操作它们的便捷 shell 语法结合在一起，这是编写通用、可重用程序方面的一次重大进步。这一理念激发了“软件工具”文化的诞生，Unix 的强大和普及在很大程度上归功于此，而 shell 也成为了第一种所谓的“脚本语言（scripting language）”。如今，Unix 的系统调用接口依然在 BSD、Linux 和 macOS 等系统中得以延续。

Unix 系统调用接口已经通过 POSIX（Portable Operating System Interface，便携式操作系统接口）标准进行了标准化。xv6 并不兼容 POSIX：它缺少许多系统调用（包括像 `lseek` 这样的基础调用），并且它提供的许多系统调用也与标准有所不同。我们设计 xv6 的主要目标是保持简单和清晰，同时提供一个简单的类 Unix（Unix-like）系统调用接口。已经有一些人通过增加少量系统调用和一个简单的 C 标准库对 xv6 进行了扩展，以便能够运行基础的 Unix 程序。然而，与 xv6 相比，现代内核提供了多得多的系统调用和内核服务。例如，它们支持网络、窗口系统、用户级线程、各种设备驱动程序等等。现代内核在持续快速地演进，并提供了许多超越 POSIX 标准的特性。

Unix 通过一套单一的文件名和文件描述符接口，统一了对多种类型资源（文件、目录和设备）的访问。这种理念可以扩展到更多种类的资源上；一个很好的例子是 Plan 9 [^16]，它将“一切皆文件（resources are files）”的概念应用到了网络、图形等更多领域。然而，大多数派生自 Unix 的操作系统并没有完全遵循这条路线。

文件系统和文件描述符一直是非常强大的抽象。尽管如此，操作系统接口还存在其他模型。Multics（Unix 的前身）将文件存储抽象为类似于内存的形式，从而产生了一种风格迥异的接口。Multics 设计的复杂性直接影响了 Unix 的设计者们，促使他们致力于构建更加简单的系统。

xv6 没有提供用户（users）的概念，也没有提供在不同用户之间进行安全隔离的机制；用 Unix 的术语来说，所有的 xv6 进程都以 `root` 权限运行。

本书探讨了 xv6 是如何实现其类 Unix 接口的，但其中的思想和概念绝不仅仅适用于 Unix。任何操作系统都必须在底层硬件上对进程进行多路复用（multiplex），将进程彼此隔离，并提供受控的进程间通信机制。在学习了 xv6 之后，当你去审视其他更为复杂的操作系统时，你应该也能从中看到与 xv6 底层相通的核心概念。
